## Current repair: observed local blob-to-data conversion without busy markers

The user's one manual diagnostic attempt on build `95a450a` failed at 2026-10-26 20:15:50.4879977 +08:00 with `attachment-source-changed-without-upload` in `attachmentPreparation`. The finite diagnostics show one attachment before/after, `src: blob -> data`, empty srcset before/after, `currentSrc: empty -> data`, no observed aria-busy attribute, no visible progressbar, and false busy/completion observations. Preparation returned false and the production caller did not enter Submit. These are actual safe-log facts; no image, URI or conversation was read.

The old ordering rejected the new local source before comparing its bytes, and then required a semantic busy-to-idle marker to finish preparation. Those requirements were based on synthetic fixtures and are not part of the observed page's contract. The `builtin-2026.10.26-composer-5-local-png` repair makes busy optional and keeps it as a deferral signal when it is actually present.

- Original-File binding remains mandatory: the actual selected/pasted File and each accepted local preview must have the exact same SHA-256 and byte length as the supplied PNG. Only same-origin blob URLs and bounded canonical `data:image/png;base64,` sources qualify; HTTP previews, srcset alternatives and other data types are not fetched or accepted.
- PNG signature/IHDR, at most 20 MiB, dimensions from 1x1 through 1920x1080, successful browser decoding, matching natural dimensions and `currentSrc == src` are required. Data URI grammar/size is checked before a local fetch. An explicit busy signal still prevents preparation. Its absence no longer prevents a decoded, byte-proven local image from preparing.
- A blob can become data while Send remains disabled after initial preparation. Before invocation, a separate bounded local-proof probe verifies that single owned image again against the retained original-File proof. It updates the saved local source only after byte equality, decode and unchanged target checks. The final synchronous invocation probe still strictly compares the latest proven source, srcset/currentSrc, form, exact text, chat context, Voice and send controls. A further change in that gap is rejected. Cancellation and automatic audio guards are checked again after the asynchronous proof and before that final probe.
- The local proof is bounded to two seconds, and a changed image's decode to two seconds; the existing eight-source limit, preparation/submit polling budgets, one submit permit and no repeated selection/paste rules remain. No filename, count, marker, enabled button or delay establishes content identity by itself. Diagnostics preserve the original before/after source categories for a successfully re-proved transition without returning source values or hashes.

Windows validation passed: Release build with zero warnings/errors, 130 .NET tests, 70 production-script Edge regressions, 83 production-C# WebView2 workflow assertions, and formatting. The new exact scenario covers blob-to-data with no busy/completion signal, both during preparation and after preparation while Send is disabled, with one click only. Different content, malformed/remote/oversize data, oversized source files/dimensions, changed context/form/text/Voice and cancellation cannot click or obtain a retry permit. Fixtures intercept requests and use only synthetic images. The new portable output is separate from the running diagnostic build, under `artifacts/upload-local-png-win-x64`.

The actual manual attempt's specific temporary PNG had already been deleted by normal cleanup when checked. No other screenshot was searched, and no private data URI was inspected. Thus the actual File-to-data byte equality has **not** been measured. This repair is verified for exact PNG-byte equivalence; a re-encoded or resized preview with different bytes remains rejected. A byte mismatch alone would not establish different pixels, but no approximate hash or unproven pixel fallback was added. ## Behavior

- All probes use one resolver for `#prompt-textarea`, `voice-mode-composer`, and the live-observed `form[data-chatgpt-composer] [role="textbox"][contenteditable="true"]` structure. The new editor must belong to the marked form; a nested foreign form is rejected. Hidden, disabled, readonly and inert editors are excluded; two eligible editors still fail closed. There is no page-wide arbitrary textbox fallback. An empty contenteditable paragraph is recognized without discarding whitespace text drafts.
- File inputs must belong to the resolved form or explicit Voice container. External inputs with an explicit matching form owner are supported. Multiple native inputs are never selected arbitrarily. With absent or ambiguous native inputs, the separate paste path targets only the same validated composer and must produce a visible attachment preview.
- The selected input and composer are checked again immediately before CDP file selection. CDP already dispatches upload events: the adapter no longer dispatches duplicate input/change events. Selecting a file alone does not prove that the application accepted an attachment.
- Preparation preserves existing drafts and unrelated attachments. Text and image preparation share the same composer and scope rules. A target or Voice transition during image preparation returns NotReady.
- A successful preparation grants one submission attempt. Cancellation and a submission attempt consume that permit. Before clicking, the same still-connected form, chat context, exact logical text, attachment identities and Voice state must match. Only CRLF/CR-to-LF text normalization is allowed; whitespace is not trimmed. A detached editor may rebind only to the unique eligible editor in that same explicitly marked form, after all other checks pass. A connected hidden editor, replaced form, changed context/text or ambiguous editor remains rejected.
- Preview wrappers and their remove-button proxies normalize to an image leaf only where that structural association is unambiguous. Source and srcset values are saved at preparation time, not reread from the old node at validation. A detached image leaf can redraw only from the exact same nonempty immutable blob/data-image source, with exact multiplicity and no extra attachments. A changed source/srcset, different image with the same filename, mutable HTTP image-node replacement, added/removed attachment or opaque marker replacement remains rejected. Source values are compared only within the page and are never returned or logged. Server-backed non-button images in the marked composer are still counted, preventing a blob-to-server transition from masquerading as attachment clearance; such a source transition is not assumed to prove equal content.
- Submit discovery also supports a unique semantic `button[type="submit"]` in the marked composer form, excluding buttons owned by another form. An unclassified marked-form state without an explicit send control remains unsafe for automatic preparation.
- Confirmation polls for at most 40 observations, 250 ms apart, using the same composer and scope. Every prepared channel must clear: text for text-only input, preview for image-only input, both for combined input. A lost marker, missing/replaced editor or partial clearance is still unconfirmed. Polling never repeats the send. The production adapter reads no replies or message history.
- Preparation diagnostics record bounded stage codes and candidate counts. Invocation now distinguishes missing/consumed state, changed context, form, editor, text, attachment count/source/node and Voice using fixed tokens only. The selected built-in rules version is logged. Diagnostics exclude message text, image URLs, HTML, screenshots, credentials and user paths. The scoped, live-observed microphone-off labels identify active Voice read-only; no microphone action is performed.
